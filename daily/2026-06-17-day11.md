## 📝 3 个问题 + 答案

### ① 高频小额支付为什么不能每笔上链？怎么保证服务方能收到钱？

每笔上链 gas 费可能高于支付金额本身，经济上不合理。

保证方案：
| 方案 | 原理 |
|------|------|
| 状态通道 | 双方链下签名记账，最后一次性上链结算 |
| L2 Rollup | 交易在 L2 打包，批量提交到 L1 |
| 闪电网络 | 多跳路由，中间人转发支付 |

共同点：每笔有加密签名，服务方有"你欠我 N USDC"的证明。不结就上链强制执行。

### ② 月预算 50 USDC，剩 2 天+1 USDC，需要 3 USDC 分析

AI 不能自己决定降级还是充值——应同时列出两个选项让用户选：

- A: 降级到免费方案（缓存数据，结果可能稍旧）→ 0 USDC
- B: 充值到足够额度 → 立即执行

用户做 tradeoff，AI 的职责是算清选项。

### ③ Web3 收据 vs 传统支付截图

| | 微信截图 | 链上收据 |
|------|------|------|

核心区别：链上收据不需要"信任我"——你可以自己验证。

## 💡 核心收获

Machine Payment 的三层设计：
1. **预算硬限制**（合约层 enforce，不是 prompt 层）
2. **链下累积+批量结算**（高频小额不能每笔上链）
3. **可验证收据**（链上存证，不可伪造）
