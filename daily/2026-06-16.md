## 📝 3 个问题 + 答案

### ① Task Graph vs 长 Prompt

Task Graph 把大任务拆成节点+依赖+停止条件，每步有明确的输入输出。
长 prompt 让 Agent 自由发挥 → 第 3 步出错它还在往第 7 步冲，不知道停。

比喻：Task Graph = 高速公路+收费站+紧急刹车，长 prompt = 野地里乱跑。

### ② 没有 State Machine，交易 pending 时的危险

- 重复发多笔交易 → gas 浪费 + 可能双重支付
- 用户关页面重开 → Agent 忘记发过交易 → 又发一笔
- 永远不知道"自己在哪一步"

### ③ Regression Set 为什么包含"用户拒绝签名"

**原因**：用户拒绝是高频事件，不是异常。拒绝可能因为看清滑点、发现金额不对、点错了。

**不做回归测试的后果**：
| 错误行为 | 后果 |
|----------|------|
| 不停重试弹签名框 | 骚扰用户 |
| 把拒绝理解为"换条路" | 绕过确认 |
| 崩溃报错 | 用户不知道发生了什么 |

**正确处理**：
1. 立即停止
2. 告知"交易未执行，资产未动"
3. 询问"修改参数还是取消"
4. 不自动重试

## 💡 核心收获

"把概率模型放进确定性流程"——Task Graph + State Machine + Human-in-the-loop + Trace + Regression Set，五层防线把 Agent 从 demo 级拉到生产级。
