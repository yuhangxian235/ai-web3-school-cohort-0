## 📝 3 个问题 + 答案

### ① 为什么"万能 RPC 工具"危险？读写分离怎么做？

万能 RPC 工具（读+写混装）的危险：读取时 prompt 若混入恶意指令，同一工具就能发交易 → 资产风险。**

读写分离做法：
- 🟢 读工具：永不发交易，自动通过
- 🟡 小额写：session key 自动签
- 🔴 大额写：必须人工确认
- ⛔ 任意合约调用：默认禁止

> 面试加分：工具应该把危险能力封装成受限接口，而不是暴露原始 RPC 端点。

### ② 转账 100 USDC 的检查流水线

1. 链准备：chain ID 对吗？网络对吗？
2. 余额检查：ETH 够 gas + USDC 够转账
3. 授权检查：allowance ≥ 100？
4. 模拟运行：会不会 revert？
5. Policy：金额在限额内？白名单？
6. 生成草稿 → 等待人工确认
7. 发送 + 等 tx 回执
8. Explorer 确认成功

### ③ Tool Log = 黑匣子

记录内容：调用人、目标、工具名、输入参数、输出结果、错误信息、chain ID、区块号、tx hash、确认人。

没有 Tool Log = 飞机没黑匣子。转了错账只能猜：是 AI 幻觉？RPC 脏数据？用户误操作？无法追溯 = 无法修复。

---

## 💡 核心收获

Web3 Tool Use 三原则：
1. **读写分离** — 读链和写链必须是不同工具
2. **权限分层** — auto → session key → human confirm → deny
3. **日志不省** — 每次调用可审计

越靠近执行，越需要 policy + simulation + human check。
