## 📝 D1-D5 对合约开发的实用度排名

| 排名 | 模块 | 核心价值 |
|------|------|----------|
| 1 🥇 | Prompt Engineering | 说清楚需求 → 直接出好代码 |
| 2 🥈 | Agent | 编译/测试/部署全自动跑 |
| 3 🥉 | RAG | 检索自己的合约文档，不瞎编 |
| 4 | Context | 长对话不丢关键信息 |
| 5 | LLM 基础 | 底盘知识，理解原理用 |

### ① 为什么 Prompt 排第一

写合约时同一个问题，prompt 差 10 倍结果差 10 倍：

- 不会写：`帮我写一个转账合约` → 没验证、没注释、没防重入
- 会写：`写一个 ERC20 转账函数，OpenZeppelin 兼容、带重入锁、事件索引正确、附带 NatSpec` → 生产级代码

Few-shot + System Prompt + Chain-of-Thought 不是玄学，是工程技能。

### ② Agent 为什么排第二

写合约不是写代码就完事——编译→测试→gas 估算→部署，Agent 自动化整个流程。Plan→Act→Observe→Replan 循环。

### ③ RAG 为什么关键

StablePay 有 15 个合约文件，AI 不知道代码里有什么。RAG 把合约 ABI/NatSpec 索引化，Agent 查函数签名时不瞎编。LLM 闭卷，RAG 开卷。

### ④ Context

长对话结对编程 30 轮后，最早的错误日志被推出上下文 → Agent 忘了最初问题。解法：关键信息（合约地址、报错日志、接口定义）主动塞回上下文。

### ⑤ LLM 基础

Token、Embedding、Transformer——不需要天天想，但得知道 prompt 为什么会被截断、不同模型为什么答得不一样。

---

## 💡 StablePay AI 助手技术分配

| 技术 | 负责 |
|------|------|
| Agent | Plan-Act-Observe 循环（接收指令→调工具→返回） |
| RAG | 索引合约 ABI + NatSpec，精准检索函数签名 |
| Context | 管理对话历史，不丢地址和交易记录 |
| Prompt | System Prompt 定义行为边界（只读，绝不签名） |
| MCP | 把合约查询能力暴露为标准接口 |

---

## ✍️ 一句话总结

五个模块不是平行的——Prompt 和 Agent 是每天用的武器，RAG 是知识外存，Context 是记忆管理，LLM 是底盘。对写合约的人，Prompt 排第一因为同样的需求，说清楚和说不清楚差 10 倍。
