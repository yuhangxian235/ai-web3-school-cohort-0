## 📝 3 个问题 + 答案

### ① Push vs Pull 支付模式，AI Agent 用哪种更安全？

（未答）

**补：**
- **Push**：付款方主动发起 → AI Agent 决定"我现在付"，安全（Agent 控制）
- **Pull**：收款方发起扣款 → AI Agent 被动被扣，危险（可能被滥用）
- AI Agent 场景首选 Push + 额度限制，Pull 只用于白名单订阅（如每月固定付 API 费）

### ② 链上仲裁不了的信息怎么办？

- 链上能仲裁的：查 receipt 状态、交付后的状态、卖家 Delivery Proof
- 链上仲裁不了的（如"Logo 好不好看"）→ 引入 **Evaluator** 做主观判断
- Evaluator 也搞不定 → 进入 **dispute** 流程，人工介入

### ③ 结算最终性 + 撤销

- 传统支付：黑盒，最终性不可查验
- 链上支付：清晰可见，每一笔都有确定状态
- 用户说"撤销"时，Agent 必须：
  1. 判断当前状态（pending？已打包？已确认？）
  2. 判断是否可撤销（已上链无法撤，只能构造反向交易）
  3. 计算 gas 损失
  4. **立即**提示用户以上情况，不等

## 💡 核心收获

Settlement 的核心问题不是"怎么转钱"，而是"钱的释放条件 = 货的确认证明"。
链上能验证的自动执行，链上不能验证的走 Evaluator → Dispute 升级。
