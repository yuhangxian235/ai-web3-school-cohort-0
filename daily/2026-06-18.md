## 📝 3 个问题 + 答案

### ① EOA 私钥 vs Agent 身份

链上合约只能验签名，不认代码。Agent 的身份在链上 = EOA 私钥对应的控制者。
如果有人换了 Agent 代码但用同一个私钥，链上合约**无法区分**。

解决方案：代码换 → Profile 必须更新。不更新 → 记录在链下信誉系统 → 降低该 Agent 的可信度。

### ② DID vs 传统用户名+密码

**多了**：
- 可解析（DID Document → 公钥/服务端点/验证方法）
- 密码学可验证（不需要信任第三方）
- 跨平台可携带（不锁死在某个服务商）
- 选择性披露（ZK 证明"我超过18岁"而不暴露生日）

**少了**：
- 密码重置机制（丢私钥 = 身份永久丢失）
- 低门槛用户体验（助记词/私钥对普通人太难）
- 社交恢复基础设施（ERC-4337 有雏形但未普及）
- 法律/合规框架（法庭上怎么认定 DID 归属？）

### ③ StablePay onlyAgent modifier 设计

```
调用者地址 → Registry 合约查 DID → 验证 Profile 哈希匹配 → 放行/拒绝
```

不用单个签名验证，而是验身份是否在注册表里且状态有效。
三层：DID（身份标识）+ Registry（注册表）+ Profile（能力/信誉/元数据）。

---

## 💡 核心收获

"Agent 的链上身份是 EOA 私钥，但完整身份是 DID + Registry + Profile 三层体系。
链上验签名，链下验能力——两者缺一不同。"

DID 不是银弹——它多了可编程性和自主权，但少了恢复机制和用户友好度。
Agent 身份 = 密码学身份 + 行为信誉 + 能力证明，三层都要。
