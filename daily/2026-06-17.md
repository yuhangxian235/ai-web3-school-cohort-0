## 📝 3 个问题 + 答案

### ① Session Key vs 直接给私钥

Session key 在合约层 enforce 额度/时间/白名单限制，AI 无法突破。
直接给私钥 = 无任何代码层限制，全靠 prompt"请求"AI 别乱花——不可靠。

本质区别：限制在代码层还是 prompt 层。

### ② 日限额 200 USDC 已用完，AI 想转第 3 笔

- 权限策略拒绝执行
- AI 告知用户"今日额度已用完（200/200 USDC），是否升级授权或等待明天"
- 不自动重试，不等用户指令不行动

### ③ Session Key 被泄露，为什么"损失可控"

4 层围栏：

| 防线 | 作用 |
|------|------|
| 金额上限 | 最多丢 session key 额度（如 500 U），拿不走全仓 |
| 时间限制 | 24h 后自动作废，攻击窗口有限 |
| 地址白名单 | 只能转白名单地址，转不到攻击者地址 |
| 操作限制 | 只能 swap，不能 approve 无限额度 |

最坏情况从"归零"降到"丢一笔小额"。

---

## 💡 核心收获

"Agent Wallet 不是给 AI 一个钱包，是给 AI 一个带围栏的钱包。"
4 层限制（额度/时间/对象/操作）在代码层 enforce，不是靠 prompt 请求。
ERC-4337 AA 钱包是 Agent Wallet 的自然底座——需要可编程的权限控制。
